Data DHCP

DHCPv4 for the data NIC runs in copper_control_plane (shared copper_dhcp library). This is where PXE clients learn where to boot from and what file to load. Needs root or CAP_NET_BIND_SERVICE for port 67.

PXE boot (next-server + boot file)

Two halves of the same instruction to a PXE client: next-server is where to go; boot file is what to download from there.

IP of the machine holding boot files (often a TFTP server). Does not have to be this DHCP host. Sent as DHCP siaddr and option 66 so picky firmware still finds it. If unset, many clients fall back to the DHCP server IP.

Path or name the client downloads — e.g. pxelinux.0, undionly.kpxe, ipxe.efi, or an HTTP URL for iPXE/UEFI HTTP Boot. With a URL, the client takes the host from the URL; next-server still matters for the first-stage TFTP load.

These should be host data NIC MACs (the ones that PXE), not BMC/OOB MACs from inventory.
